# Node.js 22, 24 and 26: the supported runtimes

**Status:** design, approach A approved on 2026-11-23. Not implemented.
**Size:** small but broad: many files, almost no logic. Released as a major for
every published package whose `engines` narrows.

## Why

The published packages promise `engines.node: ">=20.19.0"`, and CI tests Node 20,
22 and 24. That no longer matches the Node release schedule
([nodejs/Release `schedule.json`](https://github.com/nodejs/Release/blob/main/schedule.json)):

| Line | Status on 2026-11-23 | End of life |
|---|---|---|
| 20 | end of life | 2026-04-30 |
| 22 | maintenance LTS | 2027-04-30 |
| 24 | maintenance LTS since 2026-10-20 | 2028-04-30 |
| 26 | **active LTS since 2026-10-28** | 2029-04-30 |

The supported runtimes become exactly the three LTS lines: 22, 24 and 26.
Tooling already moved on: `@hey-api/openapi-ts` needs Node ≥ 22.13 and
`@changesets/cli` 3 needs ≥ 22.11, and Angular 22 refuses Node 20.

## Findings that shape the work (measured, nothing changed)

- **Node 22.16:** build, typecheck and every test suite green.
- **Node 26.13.1:**
  - build, typecheck, lint, both Angular AOT builds, and the sdk, mixins, angular, next and example suites are green;
  - **18 React tests fail** (`storage.test.ts`, `session-storage.test.ts`). Node 26 installs its own `localStorage` / `sessionStorage` globals, and in Vitest's jsdom environment they shadow jsdom's: `localStorage` reads `undefined`.
  - The runtime side of the same globals (servers sharing a store) shipped separately in viuteam/emporix-sdk#465.
- **Disabling Node's Web Storage:** `--no-experimental-webstorage` turns the globals off and is accepted by Node 22, 24 and 26. `--no-webstorage` is rejected by Node 24 (`bad option`).
- **Code:** no package source uses an API missing from Node 22 or removed in Node 26. Node 26's removals are `writeHeader`, the `_stream_*` modules and `--experimental-transform-types`, and none of them is used.
- **Publishing:** Node 26 ships npm 11.20, enough for npm Trusted Publishing (OIDC).

## Goals

- `engines.node` of all five published packages, and of the private root, covers
  exactly 22, 24 and 26 (and later LTS lines).
- CI proves it: the PR-check matrix runs 22, 24 and 26, all steps on all rows.
- The single-version workflows and local development run the active LTS, 26.
- Type definitions match the floor, so code cannot quietly use a newer Node API.
- The documentation states the new contract.

## Non-goals

- Any API change. The 11 `@deprecated` APIs stay (approach A); removing them is a
  later major.
- Raising the TypeScript `target`/`lib` (`ES2022`). Browsers consume these
  packages too; the runtime floor of Node does not set the browser floor.
- The examples' own `@types/node` and their dependency versions.

## Anti-goals

- A release that requires code changes from anyone already on Node 22 or newer.
- A CI row that skips steps. Today the Node 20 row skips the Angular AOT builds,
  and the new matrix must not carry that pattern over.

## Approaches

| | Approach | Trade-off | Decision |
|---|---|---|---|
| **A** | Node-only major: engines, CI, types, docs, the Node 26 test fix | Upgrade is a version bump for everyone on 22+; the deprecations wait for a second major | **picked** |
| B | A plus removing the 11 deprecations | One migration instead of two, but the release becomes a code migration with a bigger review | rejected for now |
| C | A now, a cleanup major after 2026-12-01 | Two small steps, certainly two majors | possible follow-up to A |

## Design

### `engines.node`

`"^22.12.0 || ^24.0.0 || >=26.0.0"` in `packages/{sdk,react,angular,next,mixins}/package.json`
and the root `package.json`.

- `^22.12.0`: the 22-line release with flag-free `require(esm)`. This is the same reason the old floor was 20.19.0 (commit `5f330d52`).
- The odd, non-LTS lines 23 and 25 are excluded.
- `>=26.0.0` stays open for 27, which under the new release schedule becomes LTS itself.

**Changed from the approaches message:** the Angular package uses the same range,
**not** Angular 22's `^22.22.3 || ^24.15.0 || >=26.0.0`. Its peer range still
allows Angular 20 and 21 (`>=20.0.0 <23.0.0`), which run on Node 22.12. Angular's
own `engines` already enforces the stricter floor for Angular 22 users.

### Releases (one changeset file)

| Package | Now | Bump | Next |
|---|---|---|---|
| `@viu/emporix-sdk` | 4.12.0 | major | 5.0.0 |
| `@viu/emporix-sdk-react` | 4.11.0 | major (linked with sdk) | 5.0.0 |
| `@viu/emporix-sdk-angular` | 0.7.0 | **minor**, the breaking bump for a 0.x package (a `major` changeset would publish 1.0.0) | 0.8.0 |
| `@viu/emporix-sdk-next` | 1.0.3 | major | 2.0.0 |
| `@viu/emporix-mixins` | 1.0.3 | major | 2.0.0 |

The changeset text says what consumers need: Node 22.12+, 24 or 26 required,
nothing else changes, and Node 20 has been end of life since 2026-04-30.

### CI (`.github/workflows/`)

- `pr-check.yml`:
  - matrix `node: [22, 24, 26]`;
  - delete the Node 20 comment block and both `if: matrix.node != '20'` guards. The newest Node 22 release satisfies Angular's `^22.22.3`.
- `release.yml`, `e2e.yml`, `api-sync.yml`, `changeset-check.yml`, `pages.yml`:
  `node-version-file: .nvmrc` instead of a hard-coded version (today 24, 24, 24, 24 and 22). The next LTS move is then one line.
- `.nvmrc`: `26`.

### Node 26 test environment

The three jsdom Vitest configs (`packages/react`, `packages/angular`,
`examples/md-module`) pass `execArgv: ["--no-experimental-webstorage"]`, with a
one-line comment on why. Without it, Node's globals shadow jsdom's Web Storage
on Node 26.

- Only React fails today, but the cause is the environment, not those tests.
- The flag is valid on all three supported lines; this design removes Node 20, the only line that rejects it.
- Node-environment suites stay untouched. The SDK's storage tests stub the globals themselves.

### Types

`@types/node`: `^24.0.0` → `^22.0.0` in the five packages, matching the floor.
If `tsc` then rejects something, the package used a Node 24 API and the runtime
floor would have been a lie; fix the code, do not loosen the types.

### Documentation

- **Root `README.md`, lines 86–95:**
  - `nvm use` picks Node 26;
  - the matrix is 22, 24 and 26; release and e2e run on `.nvmrc`;
  - the runtime floor is the new range.
- **`packages/sdk/README.md`, line 8:** "Node 20.19+" becomes "Node 22.12+, 24, 26".
- **`docs/angular.md` «Version notes»:** say that the package's own floor is 22.12, and that Angular 22 and its CLI require ^22.22.3, ^24.15.0 or 26.
- **`CLAUDE.md`:** no Node statement today; nothing to change.
